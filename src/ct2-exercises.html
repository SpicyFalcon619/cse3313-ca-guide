Lesson 19 of 22 / Lecture 7

There are two answers to integer division

From 45 you can take out one complete group of 32, with 13 left over. That makes 1 the quotient and 13 the remainder. C writes whole-number division with / and remainder with %.

addi $t0, $zero, 45
addi $t1, $zero, 32
div  $t0, $t1
mflo $t2
mfhi $t3

div means divide. Its two operands are the values to divide, in order. It puts 1 in the special register LO and 13 in the special register HI. mflo means move from LO. It copies 1 into $t2. mfhi means move from HI. It copies 13 into $t3. These special registers hold division results separately from the numbered general-purpose registers.

Follow signed remainder when the input can be negative

For −17 divided by 32, the signed quotient truncates toward zero, so the quotient is 0 and the remainder is −17. This is why a mask that keeps the low five bits gives a different result here. For nonnegative values, keeping the low five bits gives the remainder after division by 32. For signed cases such as Lecture 7’s (~(arr[b] * 16)) % 32, use div and mfhi.

If arr[b] holds 1, multiplying by 16 gives 16 and bitwise NOT gives −17 in signed two’s complement. The remainder is −17. Unpack the expression in order. Load the array value, shift left by four, flip the bits with nor, then divide and read HI.

Read the job and label the values

int fill(int i, int n, int arr[]) {
    int a = 10;
    for (i = 0; i <= n; i++) {
        arr[i * 2] = ~(a & n);
    }
    return a;
}

This function overwrites its local copy of i with 0. It writes every second array element, including element 0. It returns the value a. Use $a0 for i, $a1 for n, and $a2 for the array’s base. The slide assigns a to $s0, so preserve the old value of that register. Choose temporary registers for the comparison, address, and value to store.

Build the answer in four chunks

1. Save the caller’s value and set our starting values
fill: addi $sp, $sp, -4
      sw   $s0, 0($sp)
      addi $s0, $zero, 10
      addi $a0, $zero, 0
2. Exit when i is greater than n
Check: slt $t0, $a1, $a0
       bne $t0, $zero, Done

Read the compare as “is n less than i?” If the answer is yes, the loop must stop.

3. Calculate the byte address and then the value
sll $t1, $a0, 3
add $t1, $a2, $t1
and $t2, $s0, $a1
nor $t2, $t2, $zero
sw  $t2, 0($t1)
addi $a0, $a0, 1
j Check

Each index is i * 2. Each integer takes four bytes, so the byte distance is i * 8. A left shift by three multiplies by eight. Then add the base. The store’s address and the bitwise value are separate calculations.

4. Return a and restore the saved register
Done: add $v0, $s0, $zero
      lw $s0, 0($sp)
      addi $sp, $sp, 4
      jr $ra

Copy the result to $v0 before restoring the old $s0. This function makes no other call, so $ra still has its original return address.

Check the first passes with n = 2. i takes the values 0, 1, 2, so the function writes indices 0, 2, 4. 10 & 2 has value 2, and ~2 is −3 as a signed word. The caller still gets 10 as the function result.

Recursion and factorial

Follow several calls to the same function and see what each call needs to remember.

Lesson 21 of 22 / Lecture 7

Work out factorial without assembly

Factorial multiplies the integers from 1 up to a number. For example, 3 factorial is 3 × 2 × 1 = 6. The lecture expresses that as fact(3) = 3 * fact(2). A function that calls itself is recursive. The base case stops the calls. Here, fact(0) returns 1 immediately. In the deck, the test is n < 1.

What must survive the next call?

When fact(3) asks for fact(2), it needs both its old n (3) for the final multiply and its old $ra for the return. Save those two words before changing $a0 or running jal. This example uses eight bytes per call.

fact: addi $sp, $sp, -8
      sw   $ra, 4($sp)
      sw   $a0, 0($sp)
      slti $t0, $a0, 1
      bne  $t0, $zero, Base
      addi $a0, $a0, -1
      jal  fact
      lw   $a0, 0($sp)
      mul  $v0, $a0, $v0
      j    Return
Base: addi $v0, $zero, 1
Return: lw $ra, 4($sp)
      addi $sp, $sp, 8
      jr   $ra

mul $v0, $a0, $v0 multiplies the two source values and writes their product to $v0. This listing uses a shared cleanup at Return. The slide arranges the same cleanup separately for the base case and the recursive case.

fact(3)9923 × 2 = 6
fact(2)9842 × 1 = 2
fact(1)9761 × 1 = 1
fact(0)9681

The table starts from $sp = 1000. There are four active calls at the bottom, so 32 bytes are reserved. The calls finish in reverse order, fact(0) first and fact(3) last. This is called unwinding. Why does fact(3) reload 3 after fact(2) returns?

Check my answer

$a0 was changed to 2 for the smaller call. The old 3 is still in fact(3)’s own frame, and the next multiply needs it to turn the returned 2 into 6.

Lesson 22 of 22 / CT-2 practice

Array A starts at byte 100 and holds [5, 3, 0]. $s0 holds 100. You want to pass the first two values to a function and write the answer into A[2]. Assume the course’s simplified call model.

1. What two instructions put the inputs in $a0 and $a1?
lw $a0, 0($s0)
lw $a1, 4($s0)

The first word starts at the base. The second starts four bytes later.

2. If jal is at 1008, where does the function return?

It returns to 1012. jal saves 1012 to $ra. The function returns with jr $ra.

3. What result does the function return, and how do you store it?
add $v0, $a0, $a1   # in the function
sw  $v0, 8($s0)     # in the caller, after return

The sum 8 returns in $v0. A[2] is eight bytes past the base.

4. What would change if the function called a helper?

If it needs to return through its original $ra, save that value before the new jal and restore it before returning. One saved word needs four bytes.

5. What are the four decimal fields for sw $v0, 8($s0)?

43 / 16 / 2 / 8. The opcode is 43 for sw. The base goes in rs ($s0 is number 16), the register containing the value goes in rt ($v0 is number 2), and 8 is the byte offset.
