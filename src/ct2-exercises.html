Division, remainder, HI and LO

Split 45 by 32 and copy both answers into ordinary registers.

Computer arithmetic

There are two answers to integer division

From 45 you can take out one complete group of 32, with 13 left over. That makes 1 the quotient and 13 the remainder. C writes whole-number division with / and remainder with %.

addi $t0, $zero, 45
addi $t1, $zero, 32
div  $t0, $t1
mflo $t2
mfhi $t3

div means divide. Its two operands are the values to divide, in order. It puts 1 in the special register LO and 13 in the special register HI. mflo means move from LO. It copies 1 into $t2. mfhi means move from HI. It copies 13 into $t3. These special registers hold division results separately from the numbered general-purpose registers.

Follow signed remainder when the input can be negative

For −17 divided by 32, the signed quotient truncates toward zero, so the quotient is 0 and the remainder is −17. This is why a mask that keeps the low five bits gives a different result here. For nonnegative values, keeping the low five bits gives the remainder after division by 32. For signed cases such as Lecture 7’s (~(arr[b] * 16)) % 32, use div and mfhi.

If arr[b] holds 1, multiplying by 16 gives 16 and bitwise NOT gives −17 in signed two’s complement. The remainder is −17. Unpack the expression in order. Load the array value, shift left by four, flip the bits with nor, then divide and read HI.

Check a negative remainder with multiplication

Let $t0 = −17 and $t1 = 32. Run div $t0, $t1.

  1. The quotient is 0 because −17 ÷ 32 lies between −1 and 0, and signed integer division drops the fractional part toward zero. LO becomes 0.
  2. Use remainder = dividend − quotient × divisor. That gives −17 − 0 × 32 = −17, so HI holds −17.
  3. mfhi $t3 copies −17 into $t3. A mask of 31 would give 15, which is a different answer.

Read the signed quotient and remainder separately

Start with $t0 = -17 and $t1 = 32. div $t0, $t1 finds the integer quotient by truncating toward zero, so it writes 0 to LO. The remainder is the original dividend minus the part accounted for by the quotient. Here it is -17 - (0 × 32) = -17, so HI holds −17.

div  $t0, $t1
mflo $t2        # $t2 = quotient = 0
mfhi $t3        # $t3 = remainder = -17

A bit mask for division by 32 would keep the low five bits and produce positive 15 in this case. For a signed remainder, get the value from HI.

How can you check both outputs of division together?

Multiply the divisor by the quotient and then add the remainder. Here 32 × 0 + (-17) = -17. This gets you back to the dividend, and the remainder magnitude is smaller than 32.

Machine language

Read the job and label the values

int fill(int i, int n, int arr[]) {
    int a = 10;
    for (i = 0; i <= n; i++) {
        arr[i * 2] = ~(a & n);
    }
    return a;
}

This function overwrites its local copy of i with 0. It writes every second array element, including element 0. It returns the value a. Use $a0 for i, $a1 for n, and $a2 for the array’s base. The slide assigns a to $s0, so preserve the old value of that register. Choose temporary registers for the comparison, address, and value to store.

Build the answer in four chunks

2. Exit when i is greater than n

       bne $t0, $zero, Done

Read the compare as “is n less than i?” If the answer is yes, the loop must stop.

3. Calculate the byte address and then the value
sll $t1, $a0, 3
add $t1, $a2, $t1
and $t2, $s0, $a1
nor $t2, $t2, $zero

Each index is i * 2. Each integer takes four bytes, so the byte distance is i * 8. A left shift by three multiplies by eight. Then add the base. The store’s address and the bitwise value are separate calculations.

      lw $s0, 0($sp)

Copy the result to $v0 before restoring the old $s0. This function makes no other call, so $ra still has its original return address.

Check the first passes with n = 2. i takes the values 0, 1, 2, so the function writes indices 0, 2, 4. 10 & 2 has value 2, and ~2 is −3 as a signed word. The caller still gets 10 as the function result.

Why does the function shift i by three rather than two?

Shifting by two multiplies by four, which would get the byte offset for index i. Here the index is already 2 × i. Three shifts multiply i by eight and account for both the index expression and the four bytes per integer.

Recursion and factorial

Follow several calls to the same function and see what each call needs to remember.

Functions and the stack

Work out factorial without assembly

Factorial multiplies the integers from 1 up to a number. For example, 3 factorial is 3 × 2 × 1 = 6. The lecture expresses that as fact(3) = 3 * fact(2). A function that calls itself is recursive. The base case stops the calls. Here, fact(0) returns 1 immediately. In the deck, the test is n < 1.

What must survive the next call?

When fact(3) asks for fact(2), it needs both its old n (3) for the final multiply and its old $ra for the return. Save those two words before changing $a0 or running jal. This example uses eight bytes per call.

fact: addi $sp, $sp, -8
      sw   $ra, 4($sp)
      sw   $a0, 0($sp)
      slti $t0, $a0, 1
      bne  $t0, $zero, Base
      addi $a0, $a0, -1
      jal  fact
      lw   $a0, 0($sp)
      mul  $v0, $a0, $v0
      j    Return
Base: addi $v0, $zero, 1
Return: lw $ra, 4($sp)
      addi $sp, $sp, 8
      jr   $ra

mul $v0, $a0, $v0 multiplies the two source values and writes their product to $v0. This listing uses a shared cleanup at Return. The slide arranges the same cleanup separately for the base case and the recursive case.

The table starts from $sp = 1000. There are four active calls at the bottom, so 32 bytes are reserved. The calls finish in reverse order, fact(0) first and fact(3) last. This is called unwinding. Watch the top frame give back its saved number

At the deepest point of fact(3), $sp = 968 and fact(0) is active.

  1. The base case puts 1 in $v0. Releasing that frame adds 8 to $sp, so it returns to 976 and fact(1) resumes.
  2. At 976 the saved n is 1. Load it and multiply by the returned 1. Now $v0 = 1. After releasing this frame, $sp = 984 and fact(2) resumes.
  3. The saved n at 984 is 2, so multiply 2 × 1. Finally fact(3) reloads its saved 3 at 992 and multiplies 3 × 2. The final result is 6, and $sp is back at 1000.

Try another input and predict the deepest stack pointer

For fact(2), list calls until the base case: fact(2), fact(1) and fact(0). All three calls are still active right before the first return. Each frame takes eight bytes, so the deepest point uses 3 × 8 = 24 bytes. From $sp = 1000, that reaches 976.

The base case puts 1 in $v0 and releases its eight bytes. The stack pointer returns to 984, where fact(1) has saved the n it needs for the next multiplication.

For fact(0) by itself, does this program reserve any stack space?

Yes. The first instruction reserves eight bytes before checking the condition. $sp reaches 992, then the base case returns 1 and releases those eight bytes.

MIPS practice

Array A starts at byte 100 and holds [5, 3, 0]. $s0 holds 100. You want to pass the first two values to a function and write the answer into A[2]. Assume the course’s simplified call model.

1. What two instructions put the inputs in $a0 and $a1?
lw $a0, 0($s0)
lw $a1, 4($s0)

The first word starts at the base. The second starts four bytes later.

2. If jal is at 1008, where does the function return?

It returns to 1012. jal saves 1012 to $ra. The function returns with jr $ra.

3. What result does the function return, and how do you store it?
add $v0, $a0, $a1   # in the function
sw  $v0, 8($s0)     # in the caller, after return

The sum 8 returns in $v0. A[2] is eight bytes past the base.

4. What would change if the function called a helper?

If it needs to return through its original $ra, save that value before the new jal and restore it before returning. One saved word needs four bytes.

5. What are the four decimal fields for sw $v0, 8($s0)?

43 / 16 / 2 / 8. The opcode is 43 for sw. The base goes in rs ($s0 is number 16), the register containing the value goes in rt ($v0 is number 2), and 8 is the byte offset.

Check the whole trip from memory and back

Reveal the individual answers first, then use this short trace to check how they fit together.

  1. The two loads read bytes 100–103 and 104–107. They leave the arguments 5 and 3 in $a0 and $a1.
  2. The call at 1008 records 1012 in $ra. The function leaves 8 in $v0 and returns to the caller at 1012.
  3. The caller stores 8 at 100 + 8 = 108, so the array ends up as [5, 3, 8]. The machine code for the store encodes a byte offset of 8, which happens to match the value being stored in this example.

Put memory, control flow and encoding together

Suppose a program starts at address 1000 with $s0 = 100, $t1 = 8 and the word at address 104 holding 8. Read and trace this small program before encoding anything.

1000  lw   $t0, 4($s0)
1004  beq  $t0, $t1, Done
1008  sw   $t1, 4($s0)
1012  Done: addi $v0, $zero, 1

First write the address the load uses. Then decide whether the store runs. Finally calculate the immediate field for the branch. The load and branch both have immediate fields, but they count different units.

Check the complete trace and the branch immediate

The load uses 100 + 4 = 104 and puts 8 in $t0. The branch compares 8 and 8, so it jumps straight to 1012. The store is skipped and $v0 becomes 1. For the branch field, the reference address is 1004 + 4 = 1008. The target is 4 bytes further on, so the field is 4 ÷ 4 = 1 instruction word.
