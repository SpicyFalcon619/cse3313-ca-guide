How a computer runs a program

Follow a tiny addition from a file on your drive to a result on your screen.

Learn it first
1

Follow one addition from start to finish

Imagine opening a program that adds 5 and 3. A program is a set of instructions for a computer. An instruction tells the processor to do one operation, such as adding values. Look at where the program and its values go.

WhereWhat happens
Storage (SSD or hard drive)Keeps the program when power is off.
Main memory (RAM)The operating system loads the parts needed to run the program here.
CPU and cacheThe processor runs instructions. The cache keeps nearby copies of data and instructions the CPU may need again.
OutputThe program can send 8 to the display.
2

Meet the processor from the inside

The central processing unit (CPU) is the processor. Its control circuitry reads instructions and directs the work. Its datapath carries values and does the arithmetic. A register is a small, fast place inside the CPU that holds a value while it works.

3

Read one real instruction

In add $t0, $t1, $t2, the first register is the destination and the other two are the inputs. If $t1 holds 5 and $t2 holds 3, the CPU puts 8 in $t0.

MIPS is the instruction set architecture (ISA) used in this course. An ISA specifies the instructions a processor understands. Assembly gives instructions readable names. An assembler translates them to patterns of 0s and 1s that the CPU can read.

4

Connect the pieces to performance

When a program runs, it may spend some time in the CPU and some time waiting for a drive to return data. In the next lessons you’ll measure both the time you wait and the work the processor does.

In one line

The processor runs instructions using data held in registers and memory.

Exam habit

Name the CPU’s job and where the data comes from. Use the glossary when you meet unfamiliar terms.

The 10 facts to know cold

  1. Performance = 1 / execution time. PerfA / PerfB = TimeB / TimeA. A at 10 s vs B at 15 s: A is 1.5 times as fast.
  2. Response time is one task’s time (lower is better). Throughput is work per unit time (higher is better).
  3. Clock period = 1 / clock rate. 4 GHz = 0.25 ns = 250 ps.
  4. CPU time = clock cycles × cycle time = clock cycles / clock rate.
  5. Clock cycles = IC × CPI = Σ(ICi × CPIi). Average CPI = total cycles / total IC.
  6. CPU time = IC × CPI × cycle time = IC × CPI / clock rate.
  7. IC is set by the program, ISA and compiler. CPI depends on cycles per instruction, the instruction mix and memory access time.
  8. Power ∝ ½ × C × V² × F. Voltage fell about 15% per generation (5 V to 1 V) until transistors got too leaky: the power wall.
  9. Timproved = Taffected / n + Tunaffected. If the target is not above Tunaffected, it cannot be done.
  10. Class problems: response time = CPU time + system time. A better CPU only shrinks the CPU part.

11 · Short theory deck p.4, 7, 11, 16, 17, 19 · [2–3]
  • Effect of a faster processor vs more processors (deck p.4). A faster processor lowers response time and generally raises throughput. More processors for separate tasks raise throughput. Response time generally does not change, except that it drops if tasks were waiting in a queue.
  • Elapsed time vs CPU time (deck p.7). Elapsed time counts everything: disk and memory accesses, I/O, OS overhead. It is useful but poor for comparison. CPU time excludes I/O and other programs, and splits into user and system CPU time. The focus is user CPU time.
  • What does CPI depend on? (deck p.11) The number of cycles for each instruction, the instruction mix, and memory access time. It varies by application and by implementation of the same ISA.
  • What affects performance? (deck p.16) Algorithm: IC, possibly CPI. Programming language: IC, CPI. Compiler: IC, CPI. ISA: IC, CPI.
  • The power wall (deck p.17). Power ∝ ½CV²F. Voltage was cut about 15% per generation to allow higher clock rates, from 5 V to 1 V in 20 years. Going lower makes transistors too leaky, so clock rates could not keep rising.
  • Multicore and its challenges (deck p.19). More than one processor per chip, needing explicitly parallel programming. Challenges: programming for performance, load balancing, and optimising communication and synchronisation.
  • Amdahl’s law (deck p.20). Execution time after improvement = time affected / amount of improvement + time unaffected. Improving one part does not speed up the whole program by the same factor.

CT-1 · Performance

What does faster mean?

Measure how long one job takes and how many jobs a computer can finish.

Learn it first
1

Time the same task on two computers

Start a stopwatch when the same program begins. Stop it when the result is ready. Computer A finishes in 10 seconds and B in 15 seconds. In the time B takes to finish one run, A could do one full run plus half of another at the same rate.

MeasureComputer AComputer B
Time for one run10 s15 s
Performance for that run1 / (10 s)1 / (15 s)
A’s speed relative to B15 / 10 = 1.5×Reference run
2

Name the two measurements

Response time is how long one task takes from start to finish, such as 5 seconds. Throughput is how many tasks finish per unit of time, such as 100 tasks per minute.

A faster processor can finish each job sooner. An extra core can handle another job at the same time. It can also shorten the wait for jobs that used to queue.

3

Turn the times into a speed ratio

For one run, performance is proportional to 1 / time. To find how many times as fast A is as B, put B’s time over A’s time. B’s 15 seconds divided by A’s 10 gives 1.5. The seconds cancel, so the result is a factor.

In one line

Response time measures the wait for one task. Throughput counts completed tasks per unit time.

Exam habit

Write the program and the measure you’re comparing. For speedup, divide the old time by the new time.

Check yourself
A computer finishes 100 jobs per minute. Which quantity is that?

Throughput. “Per minute” means the number of finished jobs in a time window.

Two independent jobs wait for one core. What can change if you add a second core?

The jobs can overlap, increasing throughput. Removing time spent waiting in a queue can also reduce response time.

01 Defining performance

MUST KNOWLEARN THISabout 10 min · Deck p.3–6

Asked as: “how many times faster?” and “what happens to response time and throughput if…”.

No single best machine. L4 slide 3 compares four airplanes on four criteria, from the textbook. The winner changes with the criterion: the Concorde is fastest, the Douglas DC-8-50 has the longest range, and the Boeing 747 carries the most passengers and has the highest passengers × speed.

There is no single best airplane. Similarly, there is no single best computer for every situation. Which computer performs best depends on the criteria we use, such as execution time and throughput.

09 The switch to multiprocessors

SKIMLEARN THISabout 5 min · Deck p.18–19

Asked as: short theory at most.

Uniprocessor means a computer with a single processor. From 1978 to 2002 single-processor performance rose quickly. Around 2003 growth slowed. The graph on L4 slide 43 shows annual growth falling from about 52% to 20%. Your deck’s graph (p.18) labels the two stretches 52%/year and 22%/year, so either figure is fine if you name the source.

Three reasons single-processor growth slowed (L4 slide 44)

Power consumption

More speed means more power and heat. This is the power wall.

Memory latency

The CPU sometimes waits for data from memory. Even a faster CPU is limited by memory delays.

Instruction-level parallelism (ILP)

A single core can overlap work from different instructions of one program, but only if they are independent.

Independent: can run together

a = b + c;
x = y + z;

Dependent: second must wait

a = b + c;
x = a + z;

So there is a limit to how much ILP can help.

Multicore (L4 slide 45)

  • A multicore processor has two or more cores on one chip. Single-core has one. Quad-core has four.
  • Multiple cores can run different programs, or different parts of one program, at once. That improves throughput.
  • ILP vs multicore: ILP is one core overlapping independent instructions of the same program. Multicore is several cores working at once, and each core may also use ILP.
  • Several cores at moderate clock frequencies can sometimes give better performance per watt than one core at a very high frequency.

Challenges of parallel programming (L4 slide 46)

More cores do not automatically speed up one program. Three challenges:

Programming for performance

Some parts depend on others and cannot run at the same time, just like dependent instructions.

Load balancing

Work must be spread evenly. If one core gets 90% of it, the others finish early and sit idle.

Communication and synchronisation

Cores sometimes need each other’s results. A core waits until the result is ready.

Even if the parallel parts run twice as fast, the sequential parts still take the same time. So the whole program does not become twice as fast. The law applies whenever you improve only part of a program (L4 slide 47).

Timproved = Taffectedn + Tunaffected
Speedup = Original timeNew time   |   Maximum speedup = Original timeMinimum time

Taffected is the original time of the part you improve. Tunaffected is the time of the rest, which does not change. n is how many times faster the affected part becomes. Do not confuse n with the overall speedup.

Worked example (L4 slides 49–53)

A program takes 100 s: 80 s of multiplication and 20 s of everything else.

2×
Multiplication 2× faster: Timproved = 80/2 + 20 = 60 s. Speedup = 100/60 ≈ 1.67, not 2.
5×?
For 5× overall, Timproved = 100/5 = 20 s. Then 20 = 80/n + 20, so 80/n = 0, which is impossible for any finite n. Can’t be done.
LIMIT
Even with infinitely fast multiplication the 20 s remains. Maximum speedup = 100/20 = 5.
4.9999×
Required time = 100/4.9999 ≈ 20.0004 s, so 80/n ≈ 0.0004 and n ≈ 200,000. The closer to 5×, the faster multiplication must become.

Make the common case fast (L4 slide 53)

Operation takes 80 s of 100

2× faster gives 40 + 20 = 60 s. Speedup = 100/60 ≈ 1.67×.

Operation takes 2 s of 100

2× faster gives 1 + 98 = 99 s. Speedup = 100/99 ≈ 1.01×.

Learn the register agreement

A calling convention is an agreement about registers. Put the first four inputs in $a0 through $a3. Put results in $v0 and, when needed, $v1. $ra holds a return address. $sp holds the address of the current top of the stack.

If a callee changes a saved register $s0–$s7, it must restore that register before returning. The caller must protect any live temporary $t0–$t9 value it still needs after a call. In the slide’s example, $s0 starts at 50. The callee saves 50, reuses the register, then restores 50.

3

Reserve, save, restore, release

The stack is a region of memory managed in last-in, first-out order. The portion reserved for one active call is its stack frame. With $sp at 1000, addi $sp, $sp, -4 moves it to 996 and reserves bytes 996–999. sw $s0, 0($sp) writes 50 there. Before returning, lw $s0, 0($sp) reloads it. Add 4 to $sp to release the frame.

In the four-register example, subtract 16. The lecture places $s0, $s1, $s2, and $s3 at offsets 12, 8, 4, and 0. Restore from the same offsets, add 16 back, then return.

4

Protect the return address when calls nest

A leaf function calls no other functions. A non-leaf function makes a call. Each jal changes $ra, so a non-leaf function needs to preserve its incoming return address before its own jal. The guide uses the slides’ simplified model where jal saves PC + 4. Classic MIPS with a delay slot links to PC + 8.

Recursion means a function calls itself with a smaller problem. For fact(3), the calls are 3, 2, 1, 0. Each saves a word for n and one for the return address, so the deep point uses 32 bytes. The base case returns 1 at 0. As the calls return, multiply back by 1, 2, and 3 to produce 6, releasing a frame at each return.

In one line

Pass inputs in $a registers, leave results in $v registers, and restore the stack before returning.

Exam habit

Draw the stack frame as addresses bottomed by $sp. Save an incoming $ra before a nested call.

Check yourself
What does $ra hold immediately after jal at address 1004?

1008 in the lecture’s no-delay-slot model. jr $ra will return there.

What does $sp contain after reserving one word from 1000?

996. The actual saved word lives in memory at that address.

Why must each factorial call save its own argument?

The next call changes $a0. The old value is needed for multiplication when the next call returns.

2
Write the bits with the right widths


A bit is a 0 or 1. Binary places count in powers of two, so 9 is 8 + 1, written 1001. A register gets a five-bit slot, so write 01001. Add zeros on the left until each field fits its assigned width. Then join the fields in order.
Hexadecimal (hex) writes a group of four bits as one digit, using 0–9 and A–F. Group the joined instruction in fours starting from the left. 3

There are three layouts. Read the first six bits, the opcode, to select an operation or an operation group. For these R-type operations the opcode is zero, and funct identifies the exact operation.

4
Read an immediate as the instruction intends


In I-type, the last 16 bits may represent a literal value, a byte offset, or an instruction offset. addi, lw, sw, beq, and bne interpret this field as signed. Branch and jump fields
Find the target address, then decide what the instruction actually stores.


Learn it first


1
Start at the next address


The program counter (PC) is the address of the current instruction. With four-byte instructions, the next address is PC + 4. A label is a name for an address. For the lecture’s branch from 1000 to 1104, start measuring from 1004.
StepWorking
Origin1000 + 4 = 1004


Distance in bytes1104 − 1004 = 100


Distance in instructions100 / 4 = 25


Recover the target1004 + 25 × 4 = 1104


2
Keep the three address rules apart


lw and sw add their signed byte offset to a base register. They store the byte offset directly. beq and bne store a signed count of four-byte instructions from PC + 4. A branch to an earlier address uses a negative count.
j and jal store bits 27 through 2 of an aligned target. Restore two zero bits on the right and take the upper four bits from PC + 4. In the lecture’s low-address examples, those high bits are zero, so j 2000 stores 2000 / 4 = 500 and jal 10000 stores 10000 / 4 = 2500.


3
Test whether a made-up encoding can fit


For the lecture’s 16-bit processor with 16 registers and a three-bit opcode, each register needs four bits, leaving 16 − 3 − 4 − 4 = 5 bits. With an unsigned byte offset and two-byte elements, offsets 0, 2, …, 30 reach 16 elements directly from that base.
For 256 registers, a 32-bit instruction and a six-bit opcode, the immediate becomes 10 bits. An unsigned field then tops out at 1023, so a byte offset of 1200 and a literal 1024 both need a different instruction sequence. For 1000 registers, round up to 10 bits per register. The six-bit immediate tops out at 63 unsigned, so the second-largest byte offset is 62. These limits describe one field with one base, and the signed case has a different range.
In one line
Memory offsets use bytes. Branch offsets use instruction words from PC + 4. Jumps encode part of an aligned target address.

−32,768 to 32,767 instruction words. Multiply by four for the displacement in bytes.

Short answers built only from what the slides say. Learn the key phrases.

    
    
      
  • Response time vs throughput. Response time is how long one task takes (lower is better). Throughput is how many tasks finish in a given time (higher is better). A faster processor improves both. Adding cores mainly improves throughput.
    • 
      
  • Elapsed time vs CPU time. Elapsed time is the total time from start to finish, including I/O, OS overhead and waiting. CPU time is only the time the CPU executes the program’s instructions (user) plus OS instructions on its behalf (system).
    • 
      
  • Why raising clock rate stopped working: the power wall. Power = capacitive load × voltage2 × frequency. Higher frequency raises power and heat. Voltage cannot be lowered forever, and cooling cannot remove unlimited heat. So clock rate cannot keep rising.
    • 
      
  • Why single-processor growth slowed. Power consumption (the power wall), memory latency (the CPU waits for memory), and limited instruction-level parallelism (dependent instructions must wait).
    • 
      
  • Challenges of parallel programming. Programming for performance (dependencies), load balancing (uneven work leaves cores idle), and communication and synchronisation (cores wait for each other’s results).
    • 
      
  • State Amdahl’s law. Improving only one part of a program does not improve the whole by the same factor. Timproved = Taffected/n + Tunaffected. The unaffected part limits the speedup, so the maximum is original time divided by the unaffected time.
    • 
      
  • Why is MIPS misleading? It ignores differences in instruction complexity, in ISA, and in CPI. A machine can have higher MIPS and still take longer. CPU execution time is the reliable measure.
    • 
      
  • What affects CPU performance? Algorithm, programming language and compiler affect IC and CPI. The ISA affects IC, CPI and clock cycle time.

9 · Theory: the power wall and multicore 181, 213, 221, 231 · [2]

      
What is the power wall, and why did it lead to multicore processors?

      
WRITE
        
POINT 1
Dynamic power = ½ × capacitive load × voltage² × frequency.

        
POINT 2
For years clock rates went up, and voltage was lowered (5 V down to about 1 V) to keep power under control.

        
POINT 3
Voltage cannot drop much further, because transistors start to leak current. Raising the clock any more makes the chip too hot to cool. That limit is the power wall.

        
POINT 4
So designers stopped raising the clock and put several cores on one chip. Performance now comes from running work in parallel, which needs parallel programs.

15 · CPU time of a MIPS code listing 241, deck Problem 02 · [4]

      
Clock 2 GHz. CPI: addi 1, add 1, bne 3. How many instructions run, and what is the CPU time?
addi $t0,$zero,0 · addi $t1,$zero,3 · loop: add $s0,$s0,$t0 · addi $t0,$t0,1 · bne $t0,$t1,loop

      
WRITE
        
IDEA
Count executed instructions, not lines. Lines inside the loop run once per pass, so trace the loop first.

        
TRACE
t0 = 0, t1 = 3. Pass 1: t0 becomes 1, 1 ≠ 3, jump back. Pass 2: t0 becomes 2, jump back. Pass 3: t0 becomes 3, 3 = 3, fall through. The loop runs 3 times.

        
COUNT
Before the loop: 2 addi. Each pass: add, addi, bne = 3 instructions × 3 passes = 9. Total = 11 instructions

        
CYCLES
Before: 2 × 1 = 2. Each pass: 1 + 1 + 3 = 5, times 3 = 15. Total = 17 cycles.

        
TIME
CPU time = 17 / (2 × 109) = 8.5 ns

      
TRAPbne runs on every pass, including the last one where it does not jump. It still costs its 3 cycles.

    


    
16 · Response time with system time class notes, Types 1–4 · [3]

      
A program has 6 s of CPU time and 4 s of system time. You want the response time to be 2× faster by improving the CPU only. Find the improvement factor. Could you make it 3× faster?

      
WRITE
        
IDEA
Response time = CPU time + system time. Improving the CPU shrinks only the 6 s. The 4 s of system time is the unaffected part.

        
STEP 1
Response time = 6 + 4 = 10 s. Target for 2× = 10 / 2 = 5 s.

        
STEP 2
5 = 6/n + 4 ⇒ 6/n = 1 ⇒ n = 6. The CPU must become 6 times faster.

        
3×
Target = 10 / 3 = 3.33 s, but the system time alone is 4 s. Impossible. Maximum speedup = 10 / 4 = 2.5.

      
TRAPMaking the CPU 2× faster does not make the response 2× faster: 6/2 + 4 = 7 s, only 1.43×. Read whether the question wants the CPU or the response time to improve.

18 · Short theory 173, 182, 191, 223 · [2 each]

      
(a) Why is MIPS a poor measure of performance? (b) Response time vs throughput: which does a faster processor improve, and which does adding processors improve? (c) Why leave I/O and OS time out when measuring a processor? (d) State Amdahl’s law.

      
WRITE
        
(a)
MIPS = instruction count / (execution time × 106). It has three problems:
1. It ignores how many instructions a program needs, so computers with different ISAs cannot be compared.
2. It changes from program to program on the same computer, because CPI changes.
3. A computer with many simple instructions can show a higher MIPS and still take longer to finish.

        
(b)
Response time is how long one task takes from start to finish. Throughput is how many tasks finish per unit time.
A faster processor improves both.
Adding processors improves throughput only. Each single task still takes the same time, unless tasks were waiting in a queue, in which case response time improves too.

        
(c)
I/O and OS time depend on disks, networks and other programs running at the same time, not on the processor. CPU time measures only the processor’s own work, so it compares processors fairly.

        
(d)
The overall speedup from improving one part is limited by how much of the time that part takes:
Timproved = Taffected / improvement factor + Tunaffected.
Example: if a part is 40% of the time, even an infinite speedup of that part gives at most 1 / 0.6 = 1.67× overall.
