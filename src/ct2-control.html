If, else, and two conditions

Use a 0 or 1 from a comparison to choose where the program goes.

Lesson 10 of 22 / Lecture 5

Set a register first, then branch

slt means set if less than. In slt $t0, $s0, $s1, ask whether $s0 is less than $s1. Write 1 to $t0 for yes and 0 for no. This instruction always continues to the next line. slti $t0, $s0, 5 compares $s0 with the immediate 5 instead.

Translate if (i < j) f = g + h; else f = g - h;. Here if means run the first assignment when the test is true, and else gives the other path. Let $s0 and $s1 hold i and j, $s2 and $s3 hold g and h, and $s4 hold f.

      slt $t0, $s0, $s1
      beq $t0, $zero, Else
      add $s4, $s2, $s3
      j Done
Else: sub $s4, $s2, $s3
Done:

If i is 3 and j is 5, the compare produces 1. The branch to Else fails, so the addition runs. The jump to Done skips the subtraction. If i is 5 and j is 3, the compare produces 0 and the branch takes the subtraction path.

Turn other comparisons into tests you already know

For i <= j, ask the opposite question, “is j less than i?” With i in $s0 and j in $s1, write slt $t0, $s1, $s0, then bne $t0, $zero, Else. When both numbers are 5, slt writes 0. The branch is skipped and the if path runs, as required when the two numbers are equal.

C uses == to test equality, != to test whether values differ, and && to require two conditions to be true. In a two-condition test, stop as soon as one condition fails.

See why a second condition can change the result

Suppose i = 3, j = 5, k = 3, g = 9, and h = 4. Test i < j && i != k. Use the register assignments above and put k in $s5.

      slt $t0, $s0, $s1   # i < j?
      beq $t0, $zero, Else
      beq $s0, $s5, Else  # i == k?
      add $s4, $s2, $s3
      j   Done
Else: sub $s4, $s2, $s3
Done:
  1. slt writes 1 because 3 < 5. The first test passes, so the CPU checks the second test.
  2. A beq between i and k jumps to the Else path when they match. Here both are 3, so i != k is false and the subtraction writes f = 9 − 4 = 5.
  3. If k were 4, the second test would pass too. The addition path would give f = 9 + 4 = 13.

Choose between addition and halving

In C, use if (x == y) sum = x + y; else x = y / 2;. Here x is $s0, y is $s1 and sum is $s3. Assume y is nonnegative so a logical right shift can halve it and discard any remainder.

      bne $s0, $s1, Else
      add $s3, $s0, $s1
      j   Done
Else: srl $s0, $s1, 1
Done:

With x = 8 and y = 8, the branch falls through and sum becomes 16. With x = 7 and y = 8, it goes to Else and x becomes 4.

Trace a condition joined by OR

In C, i < j || i == k is true as soon as either test is true. For i = 3, j = 5 and k = 4, the first comparison is true. Jump to the true path immediately. When i = 5, j = 3 and k = 5, the first comparison is false, so the equality still gets a chance.

slt $t0, $s0, $s1   # i < j?
bne $t0, $zero, Yes # true if the result is 1
beq $s0, $s5, Yes   # i == k?
j   No

Use the same register assignments as the earlier example. Here the branch checks look for a success. For an expression joined by &&, the earlier translation looked for a failure so it could exit as soon as either test failed.

Which label is reached when i = 5, j = 3 and k = 4?

slt writes 0 because 5 is greater than 3. The bne falls through, then beq falls through because 5 differs from 4. The last j goes to No.

While, for, and do-while loops

Mark the check, the work, and the way back. Then trace just two passes.

Lesson 11 of 22 / Lecture 5

Test before doing the work

A loop repeats a set of instructions called its body. In C, while (i < 5) checks the condition before each pass. The body can change i with i++, meaning add 1 to i. If i starts at 4, the body runs once, then i is 5 and the next check ends the loop.

For Lecture 5’s example while (i < 5) { A[i] = A[i] + 2; i++; }, suppose $s0 holds i and $s1 holds A’s base. Follow the check and the body separately.

Check: slti $t0, $s0, 5
       beq  $t0, $zero, Done
       sll  $t1, $s0, 2
       add  $t1, $s1, $t1
       lw   $t2, 0($t1)
       addi $t2, $t2, 2
       sw   $t2, 0($t1)
       addi $s0, $s0, 1
       j    Check
Done:

If i starts at 4, we change only A[4], then leave. If i starts at 5, we reach Done before the load. A loop that tests the same unchanging values and gets true on every check can keep running. Trace which values the body actually changes.

Where do the other loop styles put the check?

  • for lists a starting assignment, a check, and an update together. for (i = 0; i < 5; i++) initializes once, then repeats check → work → update. In assembly, put the initialization before Check.
  • do-while runs the body before the first check. Put its label on the body and branch back only when the condition holds. It executes at least once.

Watch one pass change an array

Use the while loop above with i = 4, an array base of 100, and A[4] = 7.

  1. The test 4 < 5 writes 1 to $t0. The branch to Done is skipped.
  2. The shift gives 16 and adding the base gives 116. Load 7 from 116, add 2, then store 9 at the same address.
  3. The increment changes i to 5. The jump goes back to the test, which now writes 0. The branch reaches Done before another load.

Trace a for loop and a do-while

For for (i = 0; i < 10; i++) { k++; }, put i in $t0 and k in $s0. The first check compares 0 with 10. On the tenth pass i is 9, so k increments once more. The next check sees i = 10 and exits. Starting with k = 5 gives k = 15.

      addi $t0, $zero, 0
Loop: slti $t1, $t0, 10
      beq  $t1, $zero, End
      addi $s0, $s0, 1
      addi $t0, $t0, 1
      j    Loop
End:

Start with i = 1 and sum = 0. Run do { sum += i; i++; } while (i <= 10);. The first pass adds 1 before checking. The last pass adds 10 to 45, then increments i to 11. The check is false and the final sum is 55. Starting at i = 11 with sum = 0 still runs the body once and gives sum = 11.

Use a trace table to check the first and last pass

At the exit, i is 10 even though the body last ran at i = 9. This timing is why you should label when each column is recorded.

What changes if the test is i <= 10?

The body also runs when i is 10. That gives one extra update. The next test fails at i = 11, leaving k = 16.
