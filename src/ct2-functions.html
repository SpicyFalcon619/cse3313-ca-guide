How does a function return?

Give a function 5 and 3, then follow its result and its return address.

Lesson 12 of 22 / Lecture 6

Tell the caller and the function what to share

A function is a named piece of a program that performs a job. The caller is the part asking for that job. Our caller asks addNumbers to add 5 and 3. Those input values are arguments. In MIPS, the first argument goes in $a0, the second in $a1, and the result here comes back in $v0. The function receiving the request is the callee. For more inputs, $a2 and $a3 can hold a third and fourth argument. In C, return a + b; means give the caller the result of that addition.

1000  addi $a0, $zero, 5
1004  addi $a1, $zero, 3
1008  jal  addNumbers
1012  add  $s0, $v0, $zero
1016  j    After
1020  addNumbers: add $v0, $a0, $a1
1024  jr   $ra
1028  After:

Watch the instruction address and the answer separately

The example starts at byte 1000. Follow the program counter in the order the CPU actually runs the lines.

  1. Addresses 1000 and 1004 set $a0 = 5 and $a1 = 3. At 1008, jal saves 1012 to $ra and jumps to 1020.
  2. At 1020, add writes 8 to $v0. At 1024, jr reads $ra and sends the CPU back to 1012.
  3. At 1012, the caller copies 8 to $s0. At 1016 it jumps to After. The return address was 1012, and the returned value was 8.

The jump at 1016 keeps the caller from running through the function body again. Track two separate things when you trace the code. $v0 holds the answer (8). $ra holds the address where work resumes (1012).

Use a result after returning

Call add(5, 10) with $a0 = 5 and $a1 = 10. The function puts 15 in $v0, returns with jr $ra, and the caller adds another 15 to make 30.

What changes with four arguments?

Suppose the caller computes m = 32 and n = 2 from x = 15 and y = 7. It passes x, y, m and n in $a0, $a1, $a2 and $a3. The callee computes 50 + (x + y) − (m + n), so it puts 38 in $v0. After jr $ra, the caller uses that result to set n to 38 − 7 = 31.

In the slide’s implementation, the callee copies the four inputs into $s0 through $s3. It saves those registers before using them and restores them before returning. The stack lesson shows how to save a register.

Trace an argument order that matters

In C, imagine int difference(int y, int x) { return x - y; } and the call difference(5, 10). The first value, 5, arrives in $a0 because y is the first parameter. The second, 10, arrives in $a1 because x is second. The subtraction nevertheless reads x first.

difference:
    sub $v0, $a1, $a0   # x - y = 10 - 5
    jr  $ra             # return to the caller

At the return, $v0 holds 5. The program counter takes the value in $ra. Follow the result separately from the instruction address even when both are shown in the same trace.

What result does difference(10, 5) now return?

Now $a0 holds 10 and $a1 holds 5. The same instructions compute 5 − 10 = −5 and return that value in $v0.

Where can a function save a value?

Watch a function borrow a register and give it back with the original value.

Lesson 13 of 22 / Lecture 6

Give the old value somewhere to wait

Suppose $s0 contains 50 and a function wants to use it while it works. The caller expects 50 back. The function can store 50 in the stack, an area of memory used for temporary data during calls.

$sp is the stack pointer. It holds the address of the current top of the stack. In our example, it starts at 1000. To reserve space for one four-byte word, subtract four. The word starts at byte 996 and occupies bytes 996–999.

addi $sp, $sp, -4     # reserve four bytes
sw   $s0, 0($sp)      # save 50 in memory
# The function may now use $s0.
lw   $s0, 0($sp)      # restore 50 to $s0
addi $sp, $sp, 4      # release those four bytes

Follow the original value through the save and restore

Start at $sp = 1000 and $s0 = 50. Imagine the function needs to use $s0 for a result of 8.

  1. After addi $sp, $sp, -4, the pointer is 996. The next sw puts 50 into that reserved word.
  2. The function writes 8 into $s0. Memory at 996 still holds 50, because changing the register doesn’t change the saved word.
  3. lw $s0, 0($sp) restores 50. Once it is back in the register, add 4 to $sp to free the word and return the pointer to 1000.

Save a value, replace it, then get it back

Choose what $s0 starts with and what the function writes to it. Run each line to see where the original goes.

    Read Write to

    Saving on top of the stack is often called a push. Retrieving the most recently saved item and releasing its space is a pop. The MIPS example does these jobs with address arithmetic and sw or lw. Releasing a slot changes the pointer. The old bits in memory can remain there until a later store replaces them.

    Saved registers ($s0–$s7) must have their incoming values when the called function returns. Temporary registers ($t0–$t9) can be changed across a call. If the caller needs a temporary value later, the caller protects it. In the stack visualiser, choose “Save and restore $s0” and watch the store and load use the same address.

    Draw a frame with two saved registers

    Suppose $sp starts at 1000 and a function needs to change $s0 and $s1. Reserve eight bytes with addi $sp, $sp, -8. The new base is 992. Save $s0 at 4($sp) and $s1 at 0($sp).

    Offset from 992Byte addressesSaved value
    0992–995Old $s1
    4996–999Old $s0

    At the end, load $s1 from offset 0 and $s0 from offset 4 while $sp is still 992. Then add eight to $sp, returning it to 1000. Releasing the frame tells the next call that those bytes are available again.

    What address would 4($sp) point to if you released the frame first?

    After releasing the frame, $sp is 1000, so 4($sp) points to 1004. The old $s0 was stored at 996. Restore from 996 before changing the pointer.

    Nested calls and full stack frames

    Save a return address across a second call, and track where every saved word lives.

    Lesson 14 of 22 / Lecture 6

    Why a second call needs a saved return address

    Imagine main calls outer, which calls helper. If the first call is at byte 1000, $ra gets 1004. When the second call at 1028 runs, it replaces that 1004 with 1032. Save 1004 before the second call and restore it after the helper returns.

    1000  jal outer
1004  j Done
      # The caller skips the function bodies after returning.
1020  outer: addi $sp, $sp, -4
1024  sw   $ra, 0($sp)
1028  jal  helper
1032  lw   $ra, 0($sp)
1036  addi $sp, $sp, 4
1040  jr   $ra
1044  helper: addi $v0, $zero, 8
1048  jr   $ra
1052  Done:

    Read the addresses in execution order. 1000 sends control to 1020. The call at 1028 sends control to 1044. The helper leaves 8 in $v0 and returns to 1032. After restoring the old return address, 1040 returns to 1004. $v0 still holds 8. A leaf function calls no other function. The helper is a leaf. Outer is a non-leaf function.

    Reserve one group of slots for a call

    A stack frame is the block of stack memory a call reserves for its own data. Lecture 6 saves four registers in one frame. Starting at 1000, reserve 16 bytes to put $sp at 984. Using the deck’s order, store $s0 at offset 12 (996), $s1 at 8 (992), $s2 at 4 (988), and $s3 at 0 (984). These steps before the work are the prologue. Restore from the same offsets, release the 16 bytes, and return. These steps at the end are the epilogue.

    For the lecture’s f = 50 + (g+h) - (i+j), take g,h,i,j from $a0–$a3. Put 20 and 30 in $s1 and $s2, add them into $s3, and hold (g+h)-(i+j) in $s0. Add $s3 and $s0 into $v0 before restoring the old saved registers. The result is then safe in $v0 while the saved registers go back to their original values.

    Track both return addresses through one stack slot

    Assume the example at the top starts with $sp = 1000.

    1. The call at 1000 sets $ra = 1004. At 1020 and 1024, outer reserves the word at 996 and saves 1004 there.
    2. The call at 1028 replaces $ra with 1032. The word at 996 still holds 1004. The helper uses 1032 to return to outer.
    3. At 1032, outer loads the saved 1004 back into $ra. It then frees the word, and its own jr jumps to 1004.

    Find the bad jump when a return address is overwritten

    In the nested example above, outer initially needs to return to 1004. Its jal helper writes 1032 into $ra. That lets helper return to outer correctly. When outer reaches its own jr $ra, it needs 1004 again.

    Moment$raSaved slot at 996
    After the outer call and save10041004
    Inside helper10321004
    After outer loads its saved address10041004

    Without the restore, outer’s jr would jump to 1032, back inside outer. Saving the incoming return address is what lets both calls finish.

    Which function must save the incoming $ra in this example?

    outer must save it because outer executes another jal. Helper can return using the incoming value directly because it calls no other function.
