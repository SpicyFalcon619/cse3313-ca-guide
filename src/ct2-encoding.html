How do instructions become bits?

Turn your first addition into one 32-bit instruction.

Course outline / Lesson 15 of 22 / Lecture 7 Instruction and term index

Give each part of the instruction its own space

Think back to add $t0, $t1, $t2. The CPU needs to know the operation, the two inputs and where the answer goes. The assembler puts that information in separate groups of bits called fields. It writes register numbers (8 for $t0, 9 for $t1, 10 for $t2). The current numbers inside those registers, such as 5 and 3, stay in the registers.

The format for this instruction is R type. For a regular add, the opcode is 0, the function code is 32 and the unused shift amount is 0. The rs and rt fields name the two inputs. rd names the destination.

op · 6 bits000000rs · 5 bits01001rt · 5 bits01010rd · 5 bits01000shamt · 5 bits00000funct · 6 bits100000

Write the fields left to right. Notice that $t0 appears first in the assembly text but its number goes in rd, the fourth field in the bits. To write the whole instruction in hexadecimal, split the final bit string into groups of four. Each group becomes one hex digit. Here the result is 0x012A4020.

Read a machine word back into assembly

Hexadecimal uses 0–9 then A, B, C, D, E and F for 10–15. A leading 0x marks hex. Each digit represents four bits. For example, A is 10, which is 8 + 2, so it becomes 1010.

To decode 0x012A4020, write all eight hex digits as four bits each, including the leading zero. Cut the resulting 32 bits at widths 6 / 5 / 5 / 5 / 5 / 6. Opcode 0 and function code 32 identify add. The register fields say 9, 10 and 8, which are $t1, $t2 and $t0. Put the destination first when you write assembly. The answer is add $t0, $t1, $t2.

Notice which fields some instructions leave unused

sll $t0, $t1, 2 reads $t1 through rt, writes $t0 in rd, and puts 2 in shamt (shift amount). It leaves rs at zero. jr $ra uses only rs to name register 31. Its function code is 8 and the other operand fields are zero.

Check these using the instruction encoder. It can also decode hex. On an exam, fill the decimal fields first, then write bits or hex if the question asks for them.

Try it before you move on

In add $t0, $t1, $t2, what decimal value belongs in rd?

Check my answer

8, the number of $t0. That register will receive the result. Its number goes in rd even if the result it will hold happens to be 8 as well.

I-format instructions

Read the 16-bit field in context. It can hold a number, a byte distance, or a branch distance.

Course outline / Lesson 16 of 22 / Lecture 7 Instruction and term index

Start with addi

addi $t0, $t1, 5 needs an operation, one input register, one output register, and the number 5. Its I format (immediate format) has exactly four fields. Use the opcode table and the register numbers.

The widths are 6 / 5 / 5 / 16. If the question asks for decimal fields, write 8 / 9 / 8 / 5. If it asks for binary, write each field at its required width. For −5, the last 16 bits are 1111111111111011, from the signed-number lesson.

Find the roles before filling rs and rt

  • Arithmetic and bitwise. addi, andi, ori, and slti read rs and write rt. addi and slti read a signed immediate. andi and ori zero-extend theirs.
  • Memory. In lw $s1, 200($s2), the base goes in rs, the destination in rt, and 200 goes in the last field as a signed byte offset. For sw, rt supplies the value to write. Decimal fields for the load are 35 / 18 / 17 / 200.
  • Conditional branches. beq and bne put the compared registers in rs and rt. Both are inputs. The 16-bit field uses a signed instruction distance, which you will calculate in the next lesson.

Try it before you move on

For sw $s1, 200($s2), which register supplies the address? Which supplies the stored value? Do you divide 200 by four?

Check my answer

$s2 supplies the base (rs). $s1 supplies the value to store (rt). Keep 200 as written because the load/store field already counts bytes.

Branch distances and J format

Work backwards from a label’s byte address, then decode the target from the field.

Course outline / Lesson 17 of 22 / Lecture 7 Instruction and term index

Count from the next instruction for a branch

In the lecture’s example, a bne at byte 1000 has a target at 1104. Target is the place you want to reach. Start from PC + 4, 1004, then ask how many four-byte instructions away the target is.

Branch at1000Start counting at1004Target1104

The difference is 100 bytes. Divide by four to get 25 instruction words. That 25 goes in the 16-bit field. To decode the target, multiply the field by four and add PC + 4. If the target comes before PC + 4, the distance is negative. For a branch at 108 back to 100, the field is (100 − 112) ÷ 4 = −3.

Use a different rule for j and jal

J format has two fields, a 6-bit opcode and a 26-bit target field. The target must be divisible by four, so its last two binary bits are zeros. Store bits 27 through 2 of the target address. When decoding, append two zeros on the right and take the upper four bits from PC + 4. A jump can reach targets that share those upper four bits.

For a low address such as j 2000, the upper four bits are all zero, so the field is simply 2000 ÷ 4 = 500. The opcode for j is 2 and the opcode for jal is 3. Neither field uses the branch subtraction formula.

Try one question from the slide set

At 108, encode beq $t0, $zero, END where END is 124. Write opcode 4, register 8, register 0, then (124 − 112) ÷ 4 = 3. A label names an address and uses no extra bytes. You can check yourself in the instruction encoder by replacing the label with the target address and setting the PC to 108.

Try it before you move on

If a j instruction in the low address region targets byte address 100, what goes in its 26-bit field?

Check my answer

25, because 100 ÷ 4 = 25. Subtract PC + 4 only when finding the signed field of a conditional branch.

Modified MIPS and what fits

Count the patterns, then check how many bytes or elements a field can describe.

Course outline / Lesson 18 of 22 / Lecture 7 Instruction and term index

Find the number of bits needed for a register name

Each extra bit doubles the number of names. Four bits name 16 registers. For 1000 registers, nine bits give only 512 names, and ten give 1024, so use ten. Use the smallest width that covers every register even when some of its patterns go unused.

Work the slide’s 16-bit example

There are 16 registers, a 16-bit instruction, a 3-bit opcode, and two register fields. The leftover field has 16 − 3 − 4 − 4 = 5 bits. The slide treats it as an unsigned byte offset. It reaches byte offsets 0 through 31. A 16-bit array element takes 2 bytes. The aligned starting offsets are 0, 2, 4, through 30. That is 16 elements starting at the array base.

Distinguish three different exam questions

  • Will a constant fit? With 256 registers and 32-bit instructions, subtract 6 + 8 + 8 to leave 10 bits. An unsigned 10-bit field reaches 1023, so an andi constant of 1024 fails to fit.
  • Will an array element fit directly? arr[300] of a four-byte array is 1200 bytes from the base. It cannot fit directly in that 10-bit field, and a signed field would have an even smaller positive range. A program can still calculate the full address in a register and load at offset 0.
  • What is the second-largest byte offset? With 1000 registers, 32 − 6 − 10 − 10 = 6 bits remain. An unsigned field reaches 63, so the second-largest byte offset is 62. If a question instead asks for aligned word starts, count only offsets that are multiples of the word size from an aligned base.

Always check the units and whether the question says signed or unsigned. “Largest offset”, “number of addresses”, and “number of array elements” ask for different answers.

Try it before you move on

In the 16-bit example, why is the last element at byte offset 30 when there are 32 bytes?

Check my answer

The last two-byte element occupies offsets 30 and 31. Starting it at 31 would put its second byte outside the range, and 31 is off the two-byte alignment.
