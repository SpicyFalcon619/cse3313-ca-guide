How do values reach the CPU?

Fetch the same 5 and 3 from an array, then save the result.

Lesson 7 of 22 / Lecture 5

Find the number’s address

An address is the number of a location in memory. Each address names one byte. An array is a list stored in order. In our example, A holds three four-byte integers, 5, 3 and 0. Its base address is where the first element starts. Assume $s0 holds that base, 100.

A[0]5Bytes 100–103A[1]3Bytes 104–107A[2]0Bytes 108–111

A[1] is one word after the first element. A word takes four bytes, so move four byte addresses from 100 to 104. The offset is how many bytes you move from the base.

Move a word between memory and a register

Read 4($s0) as “four bytes past the address held in $s0.” lw copies a word into a register. sw copies a word out of a register into memory.

lw  $t1, 0($s0)       # $t1 gets 5
lw  $t2, 4($s0)       # $t2 gets 3
add $t0, $t1, $t2     # $t0 gets 8
sw  $t0, 8($s0)       # A[2] gets 8

Follow the data with your finger. Memory supplies 5 and 3, the registers hold them for the addition, and the store writes 8 at byte address 108.

Send a value between memory and the CPU

Change either array value. A load copies to a register. A store copies to memory.

    See the four bytes that hold a word

    A word that starts at 104 occupies byte addresses 104, 105, 106 and 107. A standard word load starts at a multiple of four. That requirement is called alignment. Starting at 105 would be misaligned.

    For decimal value 3, the four bytes are three zero bytes and one byte holding 3. Big-endian stores the byte for the largest place value first. Little-endian stores the byte for the smallest place value first. Read across from address 104 to 107.

    Byte order104105106107
    Big-endian0003
    Little-endian3000

    A load using the same byte order assembles those bytes back into 3. lw means load word, and sw means store word.

    Try a real load and see the four bytes it touches in the word memory visualiser.

    Read a word and store it somewhere else

    Start with $s0 = 100, A[1] = 3, A[2] = 0, and $t2 = 0.

    1. lw $t2, 4($s0) uses address 100 + 4 = 104. It copies the word at bytes 104–107 into $t2.
    2. At this point $t2 = 3 and A[2] still holds 0.
    3. sw $t2, 8($s0) uses address 100 + 8 = 108. It writes 3 into bytes 108–111. Both A[1] and $t2 still hold 3.

    Copy a word out of memory, then edit the copy

    Suppose $s0 = 100 and the word at address 100 holds 5. lw $t0, 0($s0) reads addresses 100–103 and copies the value into $t0. addi $t0, $t0, 3 makes the register hold 8. The word in memory still holds 5. Only a subsequent sw $t0, 0($s0) writes the updated word back.

    Change the final store offset to 4. Which word changes?

    Start at 100 + 4 = 104, so the store writes 8 across bytes 104–107. The original word starting at 100 keeps 5.

    Try it before you move on

    If A starts at byte 100, what offset loads A[2]? What address does the CPU use?

    Check my answer

    The offset is 2 × 4 = 8. The CPU uses address 100 + 8 = 108, so the instruction can be lw $t0, 8($s0).

    Arrays and calculated addresses

    Distinguish the index, the byte offset, the address, and the value stored there.

    Lesson 8 of 22 / Lecture 5

    Use the base to find the correct element

    Imagine four-byte integers in a row. A[0] means the first integer, A[1] means the second, and 1 is the index. The base is the byte address of A[0]. The byte offset is the distance from that base in bytes. Each integer takes four bytes, so the offset is index × 4.

    For the slide’s A[12] = h + A[8];, $s3 holds A’s base and $s2 holds h. Load the value at offset 32, add h, and store at offset 48.

    lw  $t0, 32($s3)   # read A[8]
add $t0, $s2, $t0  # add h
sw  $t0, 48($s3)   # write A[12]

    Calculate an address when the index is a variable

    In A[10] = h + B[i];, the offset for A[10] stays 40. The offset for B[i] depends on the value in i. Suppose $s0 holds A’s base, $s1 holds B’s base, $s2 holds h, and $s3 holds i. The offset you write before the parentheses in lw and sw must be a constant, so do the address arithmetic in a register.

    sll $t0, $s3, 2    # t0 now holds 4*i, the byte offset
add $t0, $s1, $t0  # t0 now holds the full address
lw  $t1, 0($t0)    # t1 now holds the value B[i]
add $t1, $s2, $t1
sw  $t1, 40($s0)

    Why does an address have a limit?

    An address space is the set of possible addresses. A 32-bit address gives 232 different byte addresses, from 0 through 232 − 1. That is 4 GiB of address space. A GiB is 230 bytes. The amount of actual RAM installed is a separate question.

    Spilling means temporarily keeping a value in memory when the available registers are needed for something else. Think of it as doing a store now and a load when you need the saved value back. The stack lesson gives those temporary values a place to go.

    Keep the index, address, and loaded value separate

    Take the slide’s assignment A[10] = h + B[i]. Let A start at 100 and B at 200, with i = 3, h = 230, and B[3] = 7.

    1. sll turns i into the byte offset 3 × 4 = 12. The following add turns that offset into the address 200 + 12 = 212.
    2. The lw from address 212 puts 7 in $t1. Then add updates $t1 to 230 + 7 = 237.
    3. The store uses A’s base plus 10 × 4, so it puts 237 in the word at 140.

    Find B[3], then use the word you find

    In k = B[3] + 5;, let $s4 hold B’s starting address 200, and put k in $s1. B holds four-byte integers. Count the elements before B[3]: B[0], B[1] and B[2]. They take 12 bytes in total, so B[3] starts at 212. Imagine its value is 7.

    lw   $t0, 12($s4)  # read the word at 212 into $t0
addi $s1, $t0, 5   # compute 7 + 5, so k is 12

    Track the three roles on paper. The index is 3, the address is 212, and the data read from that address is 7. The offset and the result both happen to be 12 here. The offset comes from 3 × 4. The result comes from 7 + 5.

    Source · Tasmin Sanjida, MIPS Memory and Branches.

    What goes into k if B[3] holds 10 instead?

    The load still starts at 212 because neither the index nor the base changed. The value loaded is 10, so addi sets k to 15.

    Try it before you move on

    If i = 3 and B starts at 200, what are the index, byte offset, and address of B[i]?

    Check my answer

    The index is 3. The byte offset is 12, because each integer takes four bytes. The address is 212. A load from that address gives the value stored in B[3].

    How does the CPU choose its next line?

    Trace two possible paths using the sum you already know.

    Lesson 9 of 22 / Lecture 5

    Read one address at a time

    The program counter, or PC, is the address of the instruction being run in our lecture examples. Each MIPS instruction is four bytes wide, so when nothing redirects the CPU, address 1000 is followed by 1004. A label is a name for an instruction address.

    Skip a line if the values match

    Assume $t0 holds 8 from the addition, $t1 holds the expected answer 8, and $t2 starts at 0.

    1000  beq $t0, $t1, Done
1004  addi $t2, $zero, 1
1008  Done: add $s1, $t0, $zero

    beq means branch if equal. 8 equals 8, so the next line is Done at 1008. If the values differ, the next line is 1004. bne branches when the values differ. j Done always jumps to the label.

    A conditional branch checks a condition before changing direction. A jump with j is unconditional, meaning it jumps every time. Defining Done: gives the instruction at 1008 a label. The colon marks the definition. Use Done without a colon in a branch or jump.

    Use the addresses to trace a path. We write them on the left here to show where instructions live in memory. They are separate from the assembly you would type. An instruction and a data word can both take four bytes but serve different purposes. The region of memory for instructions is the text segment. A program can keep its arrays and variables in its data segment.

    Trace both paths through the same branch

    In the listing above, $t2 starts at 0 and the instruction at 1004 would change it to 1.

    1. If both inputs are 8, beq goes from 1000 straight to 1008. The line at 1004 never runs, so $t2 stays 0.
    2. If the first input is 8 and the second is 9, beq falls through from 1000 to 1004. That line writes 1 to $t2. Then 1008 runs.
    3. In both cases the line at 1008 copies $t0 into $s1. The branch only decides whether the middle line runs.

    Read the branch as a C if statement

    Use the program above. Treat $t0, $t1, $t2 and $s1 as value slots named actual, expected, different and saved for this trace. After the branch, the instruction at Done always runs.

    if (actual != expected) {
    different = 1;
}
saved = actual;

    If the values match and $t2 started at 9, what does $t2 hold at Done?

    It stays 9. Taken beq skips the only instruction that writes $t2. The final add writes $s1.

    In the first example, if $t1 held 9, which address would run after 1000? Why?
