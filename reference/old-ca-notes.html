The 10 facts to know cold

  1. Performance = 1 / execution time. PerfA / PerfB = TimeB / TimeA. A at 10 s vs B at 15 s: A is 1.5 times as fast.
  2. Response time is one task’s time (lower is better). Throughput is work per unit time (higher is better).
  3. Clock period = 1 / clock rate. 4 GHz = 0.25 ns = 250 ps.
  4. CPU time = clock cycles × cycle time = clock cycles / clock rate.
  5. Clock cycles = IC × CPI = Σ(ICi × CPIi). Average CPI = total cycles / total IC.
  6. CPU time = IC × CPI × cycle time = IC × CPI / clock rate.
  7. IC is set by the program, ISA and compiler. CPI depends on cycles per instruction, the instruction mix and memory access time.
  8. Power ∝ ½ × C × V² × F. Voltage fell about 15% per generation (5 V to 1 V) until transistors got too leaky: the power wall.
  9. Timproved = Taffected / n + Tunaffected. If the target is not above Tunaffected, it cannot be done.
  10. Class problems: response time = CPU time + system time. A better CPU only shrinks the CPU part.

7 · Amdahl: improvement factor, or impossible? Deck p.21 · Problem 03(ii) · [2–6]

(a) Deck p.21. A program runs in 100 s; multiply operations take 80 s. How much must multiplication improve for the program to run five times faster?

WRITE
TARGET
Timproved = 100 / 5 = 20 s. Taffected = 80 s, Tunaffected = 20 s.
FORMULA
Timproved = Taffected / n + Tunaffected, so 20 = 80/n + 20
SOLVE
80/n = 0, so n = 80/0 = ∞
ANSWER
Impossible. Even infinitely fast multiplication leaves 20 s, so 5× cannot be reached.

(b) Deck Problem 03(ii). A program takes 280 ns: 80 ns FP, 180 ns load/store (L/S), 20 ns branch. Only the L/S instructions are improved. What improvement factor makes the program 2× faster?

WRITE
TARGET
Timproved = 280 / 2 = 140 ns. Taffected = 180 ns (L/S). Tunaffected = 80 + 20 = 100 ns.
FORMULA
140 = 180/n + 100
SOLVE
180/n = 40, so n = 180/40
ANSWER
Improvement factor n = 4.5

QUICK TESTA target is possible only if it is larger than Tunaffected. In (a) the target 20 equals Tunaffected, so no. In (b) 140 > 100, so yes.

11 · Short theory deck p.4, 7, 11, 16, 17, 19 · [2–3]
  • Effect of a faster processor vs more processors (deck p.4). A faster processor lowers response time and generally raises throughput. More processors for separate tasks raise throughput. Response time generally does not change, except that it drops if tasks were waiting in a queue.
  • Elapsed time vs CPU time (deck p.7). Elapsed time counts everything: disk and memory accesses, I/O, OS overhead. It is useful but poor for comparison. CPU time excludes I/O and other programs, and splits into user and system CPU time. The focus is user CPU time.
  • What does CPI depend on? (deck p.11) The number of cycles for each instruction, the instruction mix, and memory access time. It varies by application and by implementation of the same ISA.
  • What affects performance? (deck p.16) Algorithm: IC, possibly CPI. Programming language: IC, CPI. Compiler: IC, CPI. ISA: IC, CPI.
  • The power wall (deck p.17). Power ∝ ½CV²F. Voltage was cut about 15% per generation to allow higher clock rates, from 5 V to 1 V in 20 years. Going lower makes transistors too leaky, so clock rates could not keep rising.
  • Multicore and its challenges (deck p.19). More than one processor per chip, needing explicitly parallel programming. Challenges: programming for performance, load balancing, and optimising communication and synchronisation.
  • Amdahl’s law (deck p.20). Execution time after improvement = time affected / amount of improvement + time unaffected. Improving one part does not speed up the whole program by the same factor.

01 Defining performance

MUST KNOWLEARN THISabout 10 min · Deck p.3–6

Asked as: “how many times faster?” and “what happens to response time and throughput if…”.

No single best machine. L4 slide 3 compares four airplanes on four criteria, from the textbook. The winner changes with the criterion: the Concorde is fastest, the Douglas DC-8-50 has the longest range, and the Boeing 747 carries the most passengers and has the highest passengers × speed.

There is no single best airplane. Similarly, there is no single best computer for every situation. Which computer performs best depends on the criteria we use, such as execution time and throughput.

Response time and throughput (L4 slide 4)

Response time

How long a computer takes to complete one task. Example: 5 seconds to run a program. Lower is better.

Throughput

How many tasks a computer completes in a given time. Example: 100 tasks per minute. Higher is better.

ChangeResponse timeThroughput
Replace the processor with a faster oneDecreases (each task finishes sooner)Generally increases
Add more processors or coresA single task may stay the same unless it can be divided across coresGenerally increases (tasks run at the same time)

DECK p.4Adding processors that handle separate tasks raises throughput but generally leaves response time unchanged. Exception: if tasks were waiting in a queue before, their response time drops after the change, because they no longer wait.

L4 slide 4 states the focus: this lecture measures performance by response time (execution time).

Relative performance (L4 slides 5–6)

Lower execution time means higher performance, so performance is the inverse of execution time.

Performance = 1Execution Time
PerformanceAPerformanceB = Execution TimeBExecution TimeA = n

Note the reversal: A over B in performance, but B over A in time. The result n says A is n times as fast as B.

Example (L4 slide 6). A takes 10 s and B takes 15 s. PerformanceA/PerformanceB = 15/10 = 1.5, so A is 1.5 times as fast as B.

FROM YOUR CA NOTEIn class you also wrote down what decides computer performance: processor speed, memory, storage (a hard disk against an SSD, for example), I/O devices, and software optimisation such as a better algorithm. You measured throughput as work per second. A program of 100 instructions that takes 5 s on A and 10 s on B gives 20 instructions/s on A and 10 on B, so A is better. Response time is inversely proportional to speed, throughput and performance.

02 Elapsed time vs CPU time

SHOULD KNOWLEARN THISabout 5 min · Deck p.7

Asked as: short theory.

Two ways to time a program (L4 slide 7). The slides follow one Python program that reads numbers from a file on the SSD, adds them, and writes the result.

Elapsed time

Total time from the program starting until it finishes. Includes CPU processing, I/O operations, OS overhead and any waiting. It reflects the performance of the whole system: CPU, storage and everything else.

CPU time

The time the CPU spends executing instructions for this program. Excludes time spent waiting for I/O or for other programs. It reflects the CPU work the program needs.

DECK p.7Elapsed time counts everything (disk and memory accesses, I/O, operating system overhead). It is useful but often not good for comparison. CPU time does not count I/O or time running other programs, and splits into system CPU time and user CPU time. The deck’s focus is user CPU time: the time spent executing the lines of code that are in our program.

The 10-second example (L4 slides 9–10)

PartSecondsWhat happens
User CPU time5The CPU executes the program’s own instructions, such as adding the numbers
System CPU time1The CPU executes OS instructions on behalf of the program, such as locating the file and checking permissions

NOTEThe slide says all times are hypothetical, for illustration. Time spent waiting for the SSD to return data is not CPU time.

Which one matters (L4 slide 11)

Calculator program

Millions of calculations, mostly CPU. A faster CPU improves it a lot. CPU time is the useful measure.

File-reading program

Reads a huge file from an SSD and waits often. A faster SSD helps most. Elapsed time is the useful measure because it includes the waiting.

TAKEAWAYImproving the CPU does not improve every program equally. The rest of the lecture uses CPU time (L4 slide 73).

CLASS WORDING DIFFERSYour class notes use different labels for the same idea. In class: response time = elapsed time = total completion time = CPU (execution) time + system time, where “system time” means everything that is not CPU execution (I/O, display, waiting, overhead), also called “extra time”. The slides call that part non-CPU time, and use “system CPU time” for OS instructions that run inside CPU time. In an exam problem, follow the numbers you are given: if it states an execution time and a system time, the response time is their sum. Section N is built on this.

03 The CPU clock

MUST KNOWLEARN THISabout 10 min · Deck p.8

Asked as: conversions inside calculations.

  • The CPU has an electronic clock that makes a regular signal, switching between high and low. It synchronises operations inside the processor.
  • Clock cycle: one complete repetition of the signal. During a cycle the CPU can calculate and move data. At clock boundaries it can store results.
  • Clock period (clock cycle time): the time one cycle takes.
  • Clock frequency (clock rate): the number of cycles per second.
Clock period = 1Clock frequency
4 GHz = 4,000,000,000 cycles/second
Clock period = 14 × 109 = 0.25 × 10−9 s = 0.25 ns
250 ps = 0.25 ns

Asked as: CPU time, and the clock rate needed for a target time.

To run a program the CPU needs a number of clock cycles. So CPU time is cycles multiplied by how long each cycle lasts, or cycles divided by how many cycles happen per second.

CPU time = Clock cycles × Clock period
CPU time = Clock cyclesClock rate
Clock cycles = CPU time × Clock rate   |   Clock rate = Clock cyclesCPU time

Example (L4 slide 15). A program needs 100 clock cycles and each cycle takes 2 ns. CPU time = 100 × 2 ns = 200 ns.

Two ways to cut CPU time (L4 slide 16)

Fewer clock cycles

If the CPU needs fewer cycles for the same program it finishes sooner, assuming the clock rate stays the same.

Higher clock rate

If more cycles happen each second it finishes sooner, assuming the cycle count stays the same.

B is faster even though it needs more cycles. A needs fewer cycles, but B has the higher clock rate and that wins here.

The total number of machine instructions executed to run a program. Example: a program that executes 1,000 machine instructions has IC = 1000.

The average number of clock cycles needed to execute one instruction. Different instructions take different numbers of cycles, so we use an average.

08 The power wall

Asked as: power wall theory, maybe a power ratio.

Power in CMOS (L4 slide 39)

CMOS processors are built from transistors, which are tiny switches. Each time a transistor switches between 0 and 1 it uses electrical energy. The approximate dynamic power is:

Power = Capacitive load × Voltage2 × Frequency
Capacitive load

The electrical load charged and discharged each time transistors switch. A higher load needs more energy.

Voltage

Higher voltage raises power a lot, because it is squared.

Frequency

How often the circuits switch. Higher frequency generally raises power.

  • Voltage was cut from 5 V to 1 V to save power.
  • Clock frequency rose about 1,000 times.

09 The switch to multiprocessors

SKIMLEARN THISabout 5 min · Deck p.18–19

Asked as: short theory at most.

Uniprocessor means a computer with a single processor. From 1978 to 2002 single-processor performance rose quickly. Around 2003 growth slowed. The graph on L4 slide 43 shows annual growth falling from about 52% to 20%. Your deck’s graph (p.18) labels the two stretches 52%/year and 22%/year, so either figure is fine if you name the source.

Three reasons single-processor growth slowed (L4 slide 44)

Power consumption

More speed means more power and heat. This is the power wall.

Memory latency

The CPU sometimes waits for data from memory. Even a faster CPU is limited by memory delays.

Instruction-level parallelism (ILP)

A single core can overlap work from different instructions of one program, but only if they are independent.

Independent: can run together

a = b + c;
x = y + z;

Dependent: second must wait

a = b + c;
x = a + z;

So there is a limit to how much ILP can help.

Multicore (L4 slide 45)

  • A multicore processor has two or more cores on one chip. Single-core has one. Quad-core has four.
  • Multiple cores can run different programs, or different parts of one program, at once. That improves throughput.
  • ILP vs multicore: ILP is one core overlapping independent instructions of the same program. Multicore is several cores working at once, and each core may also use ILP.
  • Several cores at moderate clock frequencies can sometimes give better performance per watt than one core at a very high frequency.

Challenges of parallel programming (L4 slide 46)

More cores do not automatically speed up one program. Three challenges:

Programming for performance

Some parts depend on others and cannot run at the same time, just like dependent instructions.

Load balancing

Work must be spread evenly. If one core gets 90% of it, the others finish early and sit idle.

Communication and synchronisation

Cores sometimes need each other’s results. A core waits until the result is ready.

10 Amdahl’s law

MUST KNOWLEARN THISabout 20 min · Deck p.20–21, Problem 03

Asked as: new time, improvement factor, or “is it possible?”.

Even if the parallel parts run twice as fast, the sequential parts still take the same time. So the whole program does not become twice as fast. The law applies whenever you improve only part of a program (L4 slide 47).

If the entire program became n times faster, Timproved = Toriginal / n. Amdahl’s law handles the case where only the affected part improves.

Timproved = Taffectedn + Tunaffected
Speedup = Original timeNew time   |   Maximum speedup = Original timeMinimum time

Taffected is the original time of the part you improve. Tunaffected is the time of the rest, which does not change. n is how many times faster the affected part becomes. Do not confuse n with the overall speedup.

Worked example (L4 slides 49–53)

A program takes 100 s: 80 s of multiplication and 20 s of everything else.

2×
Multiplication 2× faster: Timproved = 80/2 + 20 = 60 s. Speedup = 100/60 ≈ 1.67, not 2.
5×?
For 5× overall, Timproved = 100/5 = 20 s. Then 20 = 80/n + 20, so 80/n = 0, which is impossible for any finite n. Can’t be done.
LIMIT
Even with infinitely fast multiplication the 20 s remains. Maximum speedup = 100/20 = 5.
4.9999×
Required time = 100/4.9999 ≈ 20.0004 s, so 80/n ≈ 0.0004 and n ≈ 200,000. The closer to 5×, the faster multiplication must become.

Make the common case fast (L4 slide 53)

Operation takes 80 s of 100

2× faster gives 40 + 20 = 60 s. Speedup = 100/60 ≈ 1.67×.

Operation takes 2 s of 100

2× faster gives 1 + 98 = 99 s. Speedup = 100/99 ≈ 1.01×.

RULEImprove the part that takes most of the time. Speeding up a tiny part barely helps. And the part you do not improve sets the ceiling.

11 Fallacies and pitfalls

Fallacy: a processor uses very little power at low load (L4 slide 68)

Load is the percentage of the processor’s processing capacity in use. For the X4 processor:

LoadPower% of full-load power
100%295 W100%
50%246 W83%
10%180 W61%

At just 10% load it still uses 61% of full-load power. Processors in Google data centers typically run at 10% to 50% load and reach 100% load less than 1% of the time. So processors should be designed so that power falls significantly when the workload falls.

Pitfall: MIPS as a performance metric (L4 slides 69–72)

NOTEHere MIPS means Millions of Instructions Per Second, the performance metric, not the MIPS instruction set.

MIPS = Instruction countCPU execution time × 106 = Clock rateCPI × 106

Substitute CPU time = IC × CPI / clock rate and the instruction count cancels.

Why MIPS misleads (L4 slide 72)

  1. Different instruction complexity. One machine’s instructions may do more work each. Two complex instructions may do what five simple ones do.
  2. Different ISAs. A may need 100 million instructions and B 200 million for the same task, so instructions per second is not a fair comparison.
  3. Different CPI. Even on the same processor, different programs have different CPI and so different MIPS. A higher-MIPS program may still take longer.

Concluding remarks (L4 slide 73)

  • Technology: advances in technology improve performance and cost-effectiveness.
  • Power: power limits performance gains, making parallelism increasingly important.
  • Performance: CPU execution time is a better measure than MIPS. Since we focus on CPU performance, we use CPU execution time rather than elapsed time.

14 Model written answers

Short answers built only from what the slides say. Learn the key phrases.

  • Response time vs throughput. Response time is how long one task takes (lower is better). Throughput is how many tasks finish in a given time (higher is better). A faster processor improves both. Adding cores mainly improves throughput.
  • Elapsed time vs CPU time. Elapsed time is the total time from start to finish, including I/O, OS overhead and waiting. CPU time is only the time the CPU executes the program’s instructions (user) plus OS instructions on its behalf (system).
  • Why raising clock rate stopped working: the power wall. Power = capacitive load × voltage2 × frequency. Higher frequency raises power and heat. Voltage cannot be lowered forever, and cooling cannot remove unlimited heat. So clock rate cannot keep rising.
  • Why single-processor growth slowed. Power consumption (the power wall), memory latency (the CPU waits for memory), and limited instruction-level parallelism (dependent instructions must wait).
  • Challenges of parallel programming. Programming for performance (dependencies), load balancing (uneven work leaves cores idle), and communication and synchronisation (cores wait for each other’s results).
  • State Amdahl’s law. Improving only one part of a program does not improve the whole by the same factor. Timproved = Taffected/n + Tunaffected. The unaffected part limits the speedup, so the maximum is original time divided by the unaffected time.
  • Why is MIPS misleading? It ignores differences in instruction complexity, in ISA, and in CPI. A machine can have higher MIPS and still take longer. CPU execution time is the reliable measure.
  • What affects CPU performance? Algorithm, programming language and compiler affect IC and CPI. The ISA affects IC, CPI and clock cycle time.

  1. Response time vs throughput: one task’s time (lower is better) vs tasks per unit time (higher is better).

WRITE
IDEA
Each row tells you how many instructions of that kind there are (IC) and how many cycles each one takes (CPI). Multiply them to get the cycles for that row, then add the rows.
STEP 1
Cycles = Σ (ICi × CPIi) = 20×2 + 10×5 + 6×4 + 4×3 = 40 + 50 + 24 + 12 = 126 cycles
STEP 2

9 · Theory: the power wall and multicore 181, 213, 221, 231 · [2]

What is the power wall, and why did it lead to multicore processors?

WRITE
POINT 1
Dynamic power = ½ × capacitive load × voltage² × frequency.
POINT 2
For years clock rates went up, and voltage was lowered (5 V down to about 1 V) to keep power under control.
POINT 3
Voltage cannot drop much further, because transistors start to leak current. Raising the clock any more makes the chip too hot to cool. That limit is the power wall.
POINT 4
So designers stopped raising the clock and put several cores on one chip. Performance now comes from running work in parallel, which needs parallel programs.

18 · Short theory 173, 182, 191, 223 · [2 each]

(a) Why is MIPS a poor measure of performance? (b) Response time vs throughput: which does a faster processor improve, and which does adding processors improve? (c) Why leave I/O and OS time out when measuring a processor? (d) State Amdahl’s law.

WRITE
(a)
MIPS = instruction count / (execution time × 106). It has three problems:
1. It ignores how many instructions a program needs, so computers with different ISAs cannot be compared.
2. It changes from program to program on the same computer, because CPI changes.
3. A computer with many simple instructions can show a higher MIPS and still take longer to finish.
(b)
Response time is how long one task takes from start to finish. Throughput is how many tasks finish per unit time.
A faster processor improves both.
Adding processors improves throughput only. Each single task still takes the same time, unless tasks were waiting in a queue, in which case response time improves too.
(c)
I/O and OS time depend on disks, networks and other programs running at the same time, not on the processor. CPU time measures only the processor’s own work, so it compares processors fairly.
(d)
The overall speedup from improving one part is limited by how much of the time that part takes:
Timproved = Taffected / improvement factor + Tunaffected.
Example: if a part is 40% of the time, even an infinite speedup of that part gives at most 1 / 0.6 = 1.67× overall.
